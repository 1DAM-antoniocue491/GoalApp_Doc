# Motivación y justificación

La elección de este proyecto surge de la **necesidad real** que existe en el ámbito del fútbol amateur de contar con herramientas sencillas y específicas para la **gestión de competiciones**, ya que muchas ligas locales, equipos de amigos o asociaciones deportivas no disponen de soluciones adaptadas a sus necesidades.

Actualmente, la organización de este tipo de ligas suele realizarse mediante **hojas de cálculo, grupos de mensajería o aplicaciones genéricas**, lo que provoca desorganización, duplicación de información y dificultad para mantener los datos actualizados. Este proyecto pretende dar respuesta a ese problema mediante una aplicación centralizada, intuitiva y accesible desde cualquier dispositivo.

#### Adecuación al contexto académico

El proyecto ha sido seleccionado porque permite aplicar de forma práctica y coherente los conocimientos adquiridos durante el curso, integrando:

* Desarrollo de **interfaces móviles** multiplataforma.
* Implementación de una **API REST** con lógica de negocio.
* Diseño y gestión de una **base de datos relacional**.
* Control de **usuarios y permisos**.
* Trabajo colaborativo y organizado en equipo.

De este modo, el proyecto no se limita a una aplicación sencilla, sino que aborda un **caso real de desarrollo completo**, similar al que se encontraría en un entorno profesional.

#### Elección de aplicación móvil multiplataforma

Se ha optado por desarrollar una aplicación móvil multiplataforma debido a que el público objetivo (jugadores, organizadores y seguidores) utiliza mayoritariamente dispositivos móviles para consultar información deportiva.

El uso de React Native permite ofrecer una experiencia consistente en Android, iOS y web, reduciendo tiempos de desarrollo y favoreciendo la reutilización del código.

#### Valor añadido del proyecto

Este proyecto aporta valor en varios niveles:

* **Funcional**, al ofrecer una solución práctica y usable.
* **Técnico**, al emplear tecnologías modernas y una arquitectura desacoplada.
* **Organizativo**, al fomentar el trabajo en equipo, la planificación y la documentación.
* **Escalable**, ya que permite futuras ampliaciones sin modificar la base del sistema.

Además, se trata de una aplicación fácilmente demostrable, lo que facilita su presentación y evaluación.

#### Viabilidad y alcance controlado

La idea del proyecto es viable dentro del tiempo y recursos disponibles, gracias a la definición de un **MVP (Producto Mínimo Viable)** que prioriza las funcionalidades esenciales.

Este enfoque garantiza la entrega de una aplicación funcional, evitando riesgos derivados de un alcance excesivo, y permite añadir mejoras únicamente si el tiempo lo permite.

#### Conclusión

En conclusión, este proyecto ha sido elegido porque combina **utilidad real**, **interés técnico** y **adecuación al entorno académico**, permitiendo desarrollar una aplicación completa, bien estructurada y representativa de un proyecto de desarrollo de software moderno.
